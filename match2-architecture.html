How to Create Code Structure for Match-2 Game

Game Development · Unity · Architecture

1. Design Pattern and Code Architecture

When designing the code structure for a Match-2 puzzle game, the Separation of Concerns principle is essential. The architecture is split into two main layers — Logic and View — with communication between them handled entirely through Event structures. While different design patterns are applied in specific situations, the overall codebase follows an MVC/MVP architecture. The Logic layer is written in pure C# and kept completely isolated from UnityEngine. The View layer uses MonoBehaviour components to build the visual layer the player sees on screen. These two layers are connected through Controller/Presenter classes. Below is a detailed breakdown of the folder structure and script responsibilities.

1.3 Core Mechanics & Algorithms

1.3.1 GridController.ProcessClick()

When the player taps the screen, the ProcessClick() function in GridController determines how the grid should respond. ProcessClick() is an async void method that drives the game's main loop. It works step by step as follows:

  1. At the start of the function, a delegate injection method is used to pull the ignoredItems list from the view side. This list is needed to exclude items that are still in motion or haven't finished their animations from match calculations.
  2. Next, CanProcessClick() is called to validate whether the player's input is on the grid and whether the tapped item is currently moving.
  3. An affectedColumn list is created to perform column-based checks during Fall and Fill operations instead of scanning the entire board.
  4. The system enters a try block and calls ActivateItemAsync(). This method checks whether the tapped object is a Rocket using an if-else block.
    • If it is a Rocket, RocketSystem.ActivateRocketAsync() is executed. This method runs asynchronously since rockets can trigger other rockets on the grid. If a chain reaction occurs, the HandleChainReaction() method in GridController manages the flow through events.
    • If it is not a Rocket, MatchSystem.Match() is called. This function invokes MatchFinder.FindMatch() and returns the affectedColumns and WillSpawnRocket parameters.
  5. After exiting the try block, as long as the affectedColumn list is not empty, RunFallFillLoopAsync() is called. This function contains a do-while loop that continues as long as affectedColumn has elements. The reason is that after each fall/fill operation, BottomCollectSystem.CollectAsync() is called. This function checks the bottom-most item in the affected columns after fall/fill completes to see if it's a collectible item like a Duck. If so, the items are collected after a designer-configured delay, and if there are still affected columns remaining, they are returned, causing the do-while loop to continue.

Note: The purpose of this mechanism is to maintain control over the grid's visual flow. In similar blast puzzle games, player inputs are disabled during power-up creation and rocket activation sequences. For this reason, an activeActionCount parameter is used to maintain control over the grid during Rocket spawn and activation operations. If any special operation is currently active on the grid, player inputs are blocked by tracking the isGlobalLock boolean.

1.3.2 MatchSystem & MatchFinder

1.3.2.1 MatchSystem

MatchSystem calls MatchFinder.FindMatch() inside its Match() function to retrieve the matched cubes, then performs the necessary checks. Based on these checks, it calls ClearMatchCells() and DamageNeighbors(). ClearMatchCells() triggers events to destroy or merge items depending on the match condition. DamageNeighbors() checks the neighbors of matched cells and applies damage to any obstacle that implements the IDamageable interface, firing the relevant events.

1.3.2.2 MatchFinder

The MatchFinder class uses a Breadth-First Search (BFS) algorithm with HashSet and Queue collections to find match groups. After the tapped Cell is added to the Queue, the algorithm searches in a while loop until the queue is empty. It dequeues the next cell, checks its neighbors for same-colored matches, and adds them to the matchedCells list. To avoid revisiting positions, visited Cells are added to a HashSet-based visited collection. Matching neighbors are enqueued to continue the while loop.

1.3.3 Fall & Fill Systems

1.3.3.1 Fall System

The FallSystem class contains a single Fall() method. It takes an affectedColumns parameter and iterates through the affected columns using a foreach loop. Each column is scanned starting from the bottom row using a two-pointer technique.

1.3.3.2 Fill System

The FillSystem's Fill() method iterates from the top row downward through the given column using a foreach loop, performing the Fill operation for each empty Cell it finds until it hits an occupied one. During the Fill process, random items are created and the TriggerItemFill event is fired.

1.3.4 RocketSystem

RocketSystem's ActivateRocketAsync() method handles the rocket's movement. Using a distance parameter and a GridPosition[] activeDirections list, it advances through cells one by one in two directions. Thanks to Task.Delay(), it waits after each cell scan for a duration specified in GameSettings. At each cell it passes through, it applies the ApplyDamage() method. This allows rockets to trigger chain reactions if they encounter other Rockets and deal damage to items. The SpawnRocketAsync() method inside RocketSystem is called by GridController when the required conditions are met to execute rocket spawning.

1.3.5 BottomCollectSystem

The BottomCollectSystem class contains an asynchronous CollectAsync() method used to collect items like Ducks that need to reach the bottom row. The bottom-most item in each column is checked, and if it implements IBottomCollectable, the item is collected. Operations are delayed via Task.Delay() for a duration specified in GameSettings to stay in sync with animations.

1.3.6 Goal & Spawn-Quota System

The GoalManager class is responsible for processing the Moves and Goals values assigned to each level. In blast puzzle games, if the required goal amount of an IFallable object exceeds what's currently on the grid, the deficit is added to the Fill process. Therefore, inside the Initialize() function, the TargetAmount from LevelData is compared with the current count on the board. If the item is IFallable, a quota is created for the missing amount and passed to CreateRandomItem(); if it is not IFallable, the TargetAmount is set equal to its count on the grid.

1.4 View Layer

In the View layer, the item and grid animations that the player sees are primarily handled through GridView and ItemView.

  • GridView: Responsible for executing animation events on the grid in an event-driven manner. GridView holds a collection called viewDictionary that maps IGridItem logic objects to ItemView visual objects. This structure stores the data of items currently in the scene and plays animations in sync with the Logic layer. It also maintains a HashSet collection called animatingItems that tracks items currently in motion on the grid. During GridController creation, GameManager provides GridView's GetAnimatingItems() function as a delegate to GridController via dependency injection, and this function returns the animatingItems set. Additionally, GridView handles border scaling during grid creation, grid positioning, and camera orthographic size adjustment.
  • ItemView: Represents the visual counterpart of grid items in the scene and lives on the ItemViewPrefab object. It queues animation functions called by GridView and plays them sequentially. It carries an IsAnimating parameter, and changes are reported through the OnAnimationStateChanged event for use in the animatingItems collection.
  • RocketView: Inherits from ItemView and lives on the RocketPrefab. Since Rocket animations differ from other item animations, certain methods are overridden.

2. Data Structures (Scalability)

The game's data structure is built on Unity's ScriptableObject system, creating an extensible architecture. To add a new item type, a definition script is created that inherits from the ItemDefinition abstract class, holding parameters such as Logic type, Sprite, Prefab, and ColoredSprite, bridging the two layers. The ItemDatabase class, which holds a list of ItemDefinition assets, centralizes all created items in a single location that the game's code structure references.

The GameSettingsData class is also created as a ScriptableObject, holding commonly used values across the codebase such as animation timing, delay timing, fall speed, and more — allowing these values to be tweaked from the Editor without touching code.

LevelDataEditor enables the gridLayout list stored in the LevelData class to be displayed as a 2D matrix structure in the Unity Editor. It also allows placing items into desired Cells visually.
