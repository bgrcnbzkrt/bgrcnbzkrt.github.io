Architecture of a Match-2 Puzzle Game

Game Development · Unity · Architecture

Building a robust and scalable "Match-2" (blast) puzzle game requires strict adherence to the Separation of Concerns principle. In this architecture breakdown, I will explore how to decouple the Logic (Model) from the View layer using a Controller-based architecture in Unity, ensuring the game rules run independently from the visual representation.

1. Design Pattern & Code Architecture

The core logic of the game is written in pure C# and completely isolated from the UnityEngine namespace. The visual layer uses MonoBehaviour components to render the state calculated by the logic layer. The communication between the two is established via an event-driven observer pattern.

1.1. Folder Structure

  • Logic: Divided into Grid, Items, Logic Interfaces, Systems, and Builders & Factories.
  • View: Divided into Grid, UI, Feedback, and Infrastructure.
  • Managers & Controllers: Handling input, game states, and logic flow.
  • ScriptableObjects: Containing configurations, level data, and item definitions.

1.2. The Logic Layer

The Logic layer computes the grid state. It uses fundamental structures like GridPosition (a struct for coordinate mathematics) and Cell (representing each grid slot and holding references to its neighbors and occupying item).

Items such as Cube, Duck, Balloon, and Rocket all implement a base IGridItem interface. To ensure maximum flexibility, behaviors are attached via interfaces like IBottomCollectable, IDamageable, or IFallable. Systems such as FallSystem and MatchSystem act strictly upon these interfaces rather than concrete classes.

2. Core Mechanics & Algorithms

2.1. Processing Player Input

When the player taps the screen, the GridController.ProcessClick() runs an asynchronous pipeline to resolve the board state. The steps are:

  • Input Validation: Using a delegate injection, the logic fetches ignoredItems from the view to prevent matching items that are currently animating.
  • Action Resolution: If the tapped item is a Rocket, the RocketSystem.ActivateRocketAsync() is invoked, processing chain reactions. If it's a regular cube, MatchSystem.Match() is called.
  • Fall & Fill Loop: A do-while loop processes Fall and Fill mechanics for the affected columns using a two-pointer algorithm. This loop continues until all gravity physics are resolved.
  • Bottom Collection: After gravity settles, BottomCollectSystem checks if items like "Ducks" have reached the lowest row and collects them.

2.2. The Match Finder (Breadth-First Search)

The MatchFinder class utilizes a Breadth-First Search (BFS) algorithm. It uses a Queue to check adjacent cells for matching colors and a HashSet of visited cells to prevent infinite loops. The resulting matched group is then passed to the logic controller to apply damage to neighboring obstacles (like Boxes or Balloons).

3. The View Layer

The visual representation must stay perfectly synced with the logic layer, but it should not dictate the rules. The GridView class listens to logic events and orchestrates the animations. It maintains a viewDictionary mapping IGridItem to ItemView.

To avoid race conditions, ItemView components queue their animations and flag themselves as IsAnimating. The logic layer pauses input if necessary, ensuring a smooth, bug-free visual experience.

4. Data Structures & Scalability

The game is highly data-driven, leveraging Unity's ScriptableObject architecture:

  • ItemDefinition: An abstract class that holds the logic type, sprites, and prefabs for a specific item. Adding a new obstacle is as easy as creating a new definition asset and assigning its interfaces.
  • GameSettingsData: A centralized configuration file for animation timings, gravity speed, and delay parameters, allowing designers to tweak the game feel without recompiling code.
  • LevelData: A 2D matrix structure configured via custom Inspector code to design levels visually within the Unity Editor.

By enforcing this strict MVC architecture and relying heavily on interface segregation and ScriptableObjects, the puzzle game framework becomes highly scalable, allowing rapid prototyping of new mechanics and levels.
